知树 KnowTree UI v0.1
设计策略 设计系统 核心界面 组件与状态 交接
初版设计稿 · 2026-10-28

把知识丢进去，
界面只负责别挡路。

依据《产品方案 v0.4》冻结的 P0 范围，这一版给出 3 个 Tab、10 个关键界面的高保真稿和一套暗色设计系统。核心判断：记录动作必须比打开笔记软件更轻，结构只在需要时出现，失败态必须说清原因。

暗色底 · 暖金单点缀 3 Tab：树 / 知识库 / 我的 模板卡片，不依赖插画 待确认态是常驻入口

三条设计原则

  • 01
    一次点击完成收录首页常驻「丢一条」，进去只有一个输入框。不选分类、不填标题、不做必填校验。
  • 02
    结构可见，但不喧宾夺主树是背景与成就，不是操作面板。金色的面积一屏不超过 8%，只用来指路。
  • 03
    把不确定性说出口「待确认」不是错误，是正常状态。低置信、疑似重复、解析失败，各自有明确出口。
01

视觉方向：为什么是暗色 + 暖金

对齐产品方案「暗色底、单点缀色、圆角卡片、克制不花哨」

概念阶段有两版调性：亮绿卡通的「小树苗」和暗色的「发光树」。这一版取暗色 + 暖金，因为产品的使用时刻是「学完、写完、想放下」——深夜、低光、长时间阅读，暗底更耐看，也让卡片和文字成为唯一的视觉重心。吉祥物的亲和力保留，但退到「我的」页，不占关键路径。

从概念到落地，改了什么

三张概念图作为调性参考，不作为 UI 方案
  • A
    树从「插画」变成「数据」概念图里的树是手绘素材，无法承载真实节点数。改为 SVG 枝干 + 圆环节点，节点半径随条目数微调，可无限扩展。
  • B
    金色只做「生长」的语义枝干、当前 Tab、主按钮、关键数字。状态色（待确认 / 失败）单独一套，不与金色混用。
  • C
    卡片去掉 AI 插画P0 用「标题 + 摘要 + 标签 + 来源」模板，纯色底 + 细描边，保证 8 秒内可见，不等文生图。

03

核心界面

10 屏 · 覆盖主路径、冷启动与失败态 · 390 × 844

顺序按用户真实路径排：空树进入 → 丢第一条 → 看它被处理 → 处理不确定时做决定 → 翻知识库 → 打开一张卡 → 被回溯送回 → 搜索复用 → 管理数据。每一屏下方的说明是给开发的验收点，不只是设计意图。

04

组件与状态

10 个界面由 6 类组件拼成，状态用颜色 + 文案双通道表达

这套界面最大的设计风险不是不好看，而是「用户不知道现在是什么状态」。所以状态不只靠颜色，还必须有短文案和可执行动作；颜色只做辅助，色弱用户也能读懂。

按钮

一屏最多一个实心主按钮

失败文案：说原因，给退路

产品方案要求「失败必须可解释」，界面照此执行
文件已加密，读不到正文下载原件
扫描件没有文字层，先试试 OCR去识别
超过 5 万字，已截断展示看原文
禁用「处理失败，请重试」这类无信息文案。每条错误必须回答：是什么原因、内容还在不在、我现在能做什么。

三个关键交互

都要求可撤销，且撤销后不再重复犯错
  • 拖
    拖拽纠偏知识库列表长按卡片拖到节点上，松手即改；记录偏好，同类内容下次优先该节点。
  • 撤
    一键撤销入树、合并、互链都能在 6 秒内通过 Toast 撤销；撤销过的链接不再自动重建。
  • 批
    批量确认收件箱底部「全部按建议处理」，一次清空；但只对置信 ≥0.5 的条目生效。

实现优先级

先做能跑通闭环的，再补好看
  • 1
    树 + 卡片 + 收录 Sheet这三个决定首日体验，先用静态数据把布局跑通。
  • 2
    状态机与骨架7 个状态先全部有对应视觉，避免后端未就绪时前端无从显示。
  • 3
    回溯与搜索依赖数据，等 M0 阈值确定后再接真实权重。
  • 4
    动效与生长最后做，且必须支持「减弱动态」降级。
与产品方案的一处偏差，需要你确认：产品方案里树的节点是「分类 + 叶子」，本设计把节点做成可直接点击的圆环并显示条目数。这意味着 树同时承担「浏览入口」，而不只是成就展示——好处是首页有用，坏处是节点一多会拥挤。我的建议是节点超过 12 个时自动折叠为「主枝干 + 数字」，展开后再看全部。

待你拍板

  • 01点缀色用暖金，还是换冷青？
    建议暖金 #C9A96B。理由：产品气质是「长期、书卷、克制」，暖金在暗底上像旧书页的烫印；冷青更偏工具与科技，容易显得像开发者面板。换色只需改一个 token，但会影响全部截图与图标描边。
  • 02首页主视图确定是树吗？要不要给「列表模式」开关？
    建议 P0 只做树，不给开关。树是产品的差异点，列表已经在「知识库」Tab 里；两个入口同时存在会让首页变成选择题。等有用户反馈「树太满不好找」再加。
  • 03待确认的入口放在首页横幅，还是只在知识库？
    建议首页保留一条横幅，且最多显示 1 条。归类是产品的核心承诺，不确定项如果藏起来，用户会以为「AI 全对」，直到某天发现挂错了，信任反而崩得更快。
  • 04吉祥物要不要出现在首页角落？
    建议不出现，只在「我的」页。首页的视觉重心必须是树和「丢一条」；吉祥物一旦常驻，就会和主按钮抢注意力，也会让人误以为这是个养成类产品。
