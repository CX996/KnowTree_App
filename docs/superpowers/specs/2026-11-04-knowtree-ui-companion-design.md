# 知树界面与灵狐陪伴体验设计

日期：2026-11-04  
状态：对话中已通过，等待设计文档审阅  
适用：知树 Web App、移动网页与后续 App 壳层

## 1. 背景

当前功能已覆盖认证、采集、知识树、知识库、正文阅读、收件箱、回顾和 AI 状态，但界面存在以下问题：

- 登录与注册页面比业务页面完整，整体设计语言不统一。
- 页面以多个静态 HTML 为主，切换依赖整页重载，连续感不足。
- 首页只绑定七个固定分类位置，第九个之后的分类无法显示。
- 操作反馈主要依赖底部提示和简单缩放，缺少清楚的层级、状态和过渡。
- 小黑狐只有静态形象，未真正参与产品流程。
- 现有 CSS、页面标记和交互代码职责交织，继续叠加样式会加重维护成本。

本设计替代 `docs/design/DESIGN-设计契约.md` 中只允许吉祥物出现在“我的”的旧决定，也替代首页固定七个分类位置的做法。认证、权限、数据所有权和 API 安全边界不变。

## 2. 目标

1. 建立一套同时适用于手机和桌面的黑金书卷视觉系统。
2. 让用户打开首页后先看到可执行动作，再看到知识状态。
3. 减少页面切换白屏和等待感，同时保持现有静态多页架构。
4. 把小黑狐变成可动、可拖动、永久常驻的 L2 情境助手。
5. 让知识树生长和新叶数量来自真实知识行为，不引入虚假数值。
6. 保持现有登录、注册、采集、文件解析、Markdown 阅读、编辑、审核和部署能力。
7. 对手机、键盘用户、屏幕阅读器和减少动态效果用户提供等价操作路径。

## 3. 非目标

- 本轮不重写为 React、Vue 或 Next.js 单页应用。
- 不做 3D、WebGL 角色或游戏引擎。
- 不做抽卡、充值、装扮、宠物体力、等级或强制签到。
- 不允许宠物自动保存、归类、合并、删除、发布或修改用户知识。
- 本轮不追求完整四足逐帧步态。首版使用已批准的姿态动画，后续可替换为 Rive 骨骼。
- 不新增用于宠物经济或复杂活动记录的后端表。

## 4. 已确认的产品方向

### 4.1 视觉方向

采用“墨夜书页”：

- 暗色应用壳层承载导航和状态。
- 暖纸表面承载正文、采集和需要长时间阅读的内容。
- 旧金只用于当前状态、关键标识、轮廓光和数字强调。
- 小黑狐保持安静、敏锐、书卷气，不转向赛博机械或大头萌宠。

### 4.2 首页方向

首页采用“行动优先”：

1. 问候与当前情境。
2. 首要采集入口。
3. 最多一条宠物提示。
4. 待归类内容。
5. 知识树近况。

知识树紧随行动出现，不与采集入口争夺首屏。

### 4.3 宠物权限

宠物固定为 L2：

- 可以出现、移动、指向、呈现待处理状态和播放动作。
- 用户点击宠物或气泡后，可以打开对应流程。
- 不代替用户提交任何写操作。
- 删除、注销、批量修改等动作永远不能由宠物触发。

### 4.4 角色主锚点

已批准的透明角色资产：

- 生产母版：`docs/design/character/references/kt-fox-01_transparent-anchor-v1.png`
- 网页主图：`docs/design/character/references/kt-fox-01_transparent-web-v1.png`
- 动作来源：`docs/design/character/references/kt-fox-01_action-sheet-v1.jpeg`
- 已拆分动作帧：`docs/design/character/references/motion/`
- 网页优化帧：`docs/design/character/assets/pet/`

已确认的六个动作帧为站立、坐下、奔跑、嗅看、叼叶行走和回望。走动、跳跃和庆祝状态由整图位移、节奏和姿态切换组成。不得拉伸四肢或尾巴来伪装骨骼动作。

## 5. 视觉系统

### 5.1 色彩令牌

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--bg` | `#10110E` | 应用最底层 |
| `--bg-deep` | `#0A0B09` | 导航、沉浸区域 |
| `--surface` | `#171813` | 普通卡片与弹层 |
| `--surface-raised` | `#20211B` | 浮层和选中区域 |
| `--paper` | `#E7DDC7` | 主阅读纸面 |
| `--paper-high` | `#F2EBDC` | 重点采集区域 |
| `--ink` | `#28241B` | 纸面正文与标题 |
| `--text` | `#F1EBDD` | 暗色界面正文 |
| `--text-muted` | `#AAA393` | 次级说明 |
| `--gold` | `#C6A15B` | 当前状态、标记和主强调 |
| `--gold-soft` | `#DFC27F` | 轮廓光和轻强调 |
| `--moss` | `#4D5947` | 知识树、成功和自然状态 |
| `--danger` | `#D46A5E` | 错误和危险操作 |
| `--line` | `rgba(241,235,221,.10)` | 暗色分隔线 |

规则：

- 金色不同时用于大面积背景、正文和多个按钮。
- 纸面卡片使用墨色文字，不把暗色正文反向套在浅纸中。
- 错误不使用金色包装，必须保持可识别。

### 5.2 字体与排版

- 展示标题：本地优先的宋体/思源宋体回退栈。
- 界面文字：苹方、微软雅黑、Noto Sans CJK 回退栈。
- 正文：宋体回退栈，行高 `1.85–2.0`。
- 页面主标题手机为 28–34 px，桌面为 34–44 px。
- 功能按钮正文不小于 13 px，正文阅读不小于 16 px。
- 数字与英文标签可以使用窄字距大写，但不得处处使用全大写。
- 默认不依赖远程字体；若后续使用 WOFF2，必须子集化并预加载，单文件不超过 120 KB。

### 5.3 空间、圆角和层级

- 间距基于 4 px，主要使用 8、12、16、20、24、32、48。
- 小控件圆角 10–12 px，卡片 16–22 px，底部导航 18–22 px。
- 阴影只用于浮层、宠物和纸面主卡，不给所有卡片同时加阴影。
- 图标采用统一 1.6 px 线条，禁止混用表情符号作为功能图标。

### 5.4 动效节奏

- 点击反馈：90–120 ms。
- 普通过渡：160–220 ms。
- 页面或共享元素过渡：260–360 ms。
- 宠物待机：约 4.8 秒循环。
- 走动：约 4.4 秒往返。
- 奔跑：约 1.9 秒通过安全区域。
- 跳跃：约 1.2 秒完成一次起落。
- 动效只改变 `transform` 和 `opacity`，不得触发布局重排。

## 6. 应用壳层与导航

### 6.1 手机

- 视口小于 768 px 使用单列布局。
- 内容最大宽度 430 px，左右至少 18 px 安全边距。
- 底部导航固定，包含四个入口：知识树、知识库、回顾、我的。
- 采集不是第五个 Tab，首页主采集卡和允许页面上的明确按钮承担主行动。
- 底部导航遵守 `safe-area-inset-bottom`。
- 正文页保留底部导航；采集页进入聚焦模式，隐藏底部导航以保护表单空间。

### 6.2 平板

- 768–1199 px 使用 80 px 图标侧栏。
- 内容区居中，最大宽度 760 px。
- 不显示右侧上下文栏。

### 6.3 桌面

- 1200 px 以上使用 220–240 px 侧栏。
- 主内容区 680–880 px。
- 1440 px 以上可以显示约 260 px 的“今天/最近”上下文栏。
- 采集入口固定在侧栏顶部，不随内容滚动消失。
- 正文阅读列最宽 760 px，避免行长过长。

### 6.4 页面与导航映射

| 页面 | 主导航状态 | 说明 |
|---|---|---|
| `index.html` | 知识树 | 首页行动优先与知识树近况 |
| `library.html` | 知识库 | 全部知识与动态分类筛选 |
| `search.html` | 知识库 | 搜索结果沿用知识库壳层 |
| `inbox.html` | 知识库 | 待归类和疑似重复 |
| `detail.html` | 知识库 | 正文阅读、编辑和来源 |
| `capture.html` | 无 | 聚焦采集，不显示底部导航 |
| `review.html` | 回顾 | 单卡回顾闭环 |
| `me.html` | 我的 | 账号、AI 状态和偏好 |
| 登录/注册/找回密码 | 无 | 不加载宠物，不显示业务导航 |

## 7. 页面模式

### 7.1 首页

- 顶部显示品牌、问候和简短知识状态。
- 第一主卡为采集输入，支持文字、链接和文件入口。
- 首屏最多显示一条宠物提示。
- 有待归类时展示紧凑状态条，数据来自现有 `KT.inbox()`。
- 知识树只展示最有价值的 5 个动态分类和一个“查看全部”入口，不隐藏第九个之后的分类。
- 树的生长数字必须能由现有创建时间、分类数或条目数推导；无可靠数据时不显示“本周/本月”等伪统计。

### 7.2 采集

- 只保留返回、标题和必要工具。
- 输入区优先占据首屏。
- 标题、摘要、分类由 AI 建议，但提交前用户可以看见。
- 解析中显示明确阶段，不使用无尽旋转。
- 宠物以小型坐姿停留在安全区，不跑动、不出气泡。
- 成功后直接进入正文；返回行为继续遵守现有来源路径规则。

### 7.3 知识库与搜索

- 分类筛选使用可见的水平滚动或侧栏列表，不依赖七个固定节点。
- 列表卡片突出标题、摘要首行、分类、更新时间和状态。
- 空态、加载态和错误态分别设计，不用同一段“暂无内容”。
- 搜索页与知识库共享搜索输入和筛选状态。

### 7.4 正文阅读

- 阅读表面统一为暖纸色。
- 标题使用宋体展示，正文行高不低于 1.85。
- Markdown 标题、引用、代码、表格、链接和图片使用一套明确样式。
- 顶部提供来源面包屑、返回、编辑和更多操作。
- 编辑态保留未保存离开提醒；宠物缩小并停在安全位置。

### 7.5 回顾

- 一次只突出一个知识卡。
- 操作顺序固定为“继续看、稍后再看、已理解”。
- 完成后宠物播放一次短跳，不弹出红包式奖励。
- 无回顾内容时给出下一次可用时间，不制造无限空卡。

### 7.6 我的

- 账号信息和退出登录与业务设置分开。
- AI 状态、模型能力和失败原因保持可读。
- 宠物永久显示，设置中只保留“减少宠物动作”。
- 宠物偏好按设备本地保存，不强制同步。

## 8. 宠物系统

### 8.1 位置

- 手机：停在底部导航上方的右侧安全区。
- 平板：停在图标侧栏底部。
- 桌面：停在左侧栏底部；有右侧上下文栏时仍以左侧为主要归属。
- 宠物始终常驻，可拖动到视口内的任意安全位置，位置按设备保存。
- 不覆盖正文、输入框、保存按钮、通知和底部导航。

### 8.2 状态机

| 状态 | 主要素材 | 触发 | 退出 |
|---|---|---|---|
| `hidden` | 无 | 资源加载失败或页面不可见 | 资源恢复或页面重新可见 |
| `idle` | 站立 | 无操作 | 输入、提示或用户操作 |
| `listen` | 坐下 | 输入框聚焦 | 失焦或提交完成 |
| `walk` | 叼叶行走 | 页面完成加载后短距离巡游 | 目标状态出现 |
| `run` | 奔跑 | 用户点击快速入口 | 到达入口或页面跳转 |
| `sniff` | 嗅看 | AI 解析或扫描内容 | 成功、失败或取消 |
| `carry` | 叼叶行走 | 存在 1–3 条待归类 | 用户打开或关闭提示 |
| `celebrate` | 回望并短跳 | 保存或回顾完成 | 900 ms 后回到 `idle` |
| `error` | 坐下并降低重心 | 请求失败 | 用户重试或关闭错误 |

状态优先级从高到低：

```text
hidden > error > listen > celebrate > carry > sniff > run > walk > idle
```

任何事件都不能把常驻宠物变成需要用户手动恢复的隐藏状态。

### 8.3 主动提示

- 同一页面同时只显示一条气泡。
- 用户输入时不出现新气泡。
- 主动建议最多每 45 秒一次，同一会话不重复催促同一件事。
- 气泡包含明确动作词，例如“带我去看”“稍后处理”“知道了”。
- 用户关闭后，本页面本次访问不再出现同一条提示。
- 错误不能只通过宠物情绪表达，必须同时展示文字原因和可操作按钮。

### 8.4 点击行为

点击宠物打开最多三个动作：

1. 记一条。
2. 处理待归类，仅在存在待处理项时显示。
3. 看看今天的回顾。

点击气泡直接进入气泡描述的目标页面。宠物不调用写接口。

### 8.5 动作资源

首版网页帧位于 `docs/design/character/assets/pet/`：

- `stand`
- `sit`
- `run`
- `sniff`
- `walk`
- `turn`

总计约 182 KB 的 WebP 资源。后续正式接入时复制到 `apps/web/assets/pet/`，不得引用 `.superpowers` 中间目录。

`walk` 状态移动整只角色并叠加身体起伏；`celebrate` 使用回望帧做一次跳跃。它们不是连续四足步态。未来若取得 6–8 帧走路循环和 6–8 帧跑步循环，应替换素材而不改变宠物状态接口。

### 8.6 持久化

首版只使用浏览器本地存储：

- `knowtree.pet.position.v1`：宠物拖动后的视口坐标。
- `knowtree.pet.motion.v1`：用户是否主动减少宠物动作。
- `knowtree.pet.hintDismissed.v1`：当前会话已关闭的提示类型。

不新增数据库迁移。清除本地存储后恢复默认展开与正常动画。

## 9. 知识树生长

### 9.1 数据来源

- 新叶数量来自现有条目的创建时间。
- 枝杈粗细来自分类下条目数量。
- 最近活跃分类来自已有条目的更新时间；若后端没有可靠更新时间，则回退到创建时间。
- 回顾次数不虚构；没有可靠回顾记录时不显示。

### 9.2 展示规则

- 首页使用有树干、树皮、弯曲枝条和多簇叶片的自然树形，不使用圆圈节点网络图。
- 首页最多展示五个权重最高的分类。
- 多余分类通过“查看全部”进入知识库，不静默隐藏。
- 空知识库显示种下一颗种子的空态和采集按钮。
- 生长动效只在本次新增成功后播放一次，不在每次刷新重复庆祝。

## 10. 页面切换与流畅度

### 10.1 保留静态多页架构

继续使用现有 HTML 页面，通过共享壳层、预加载和过渡减少重载感。这样可以降低认证、部署和现有测试的回归风险。

### 10.2 过渡

- 支持 Cross-document View Transitions 的浏览器使用跨页面淡入和共享标题/纸面过渡。
- 不支持时立即回退普通导航，不显示空白等待层。
- 底部导航当前项使用共享元素或持续位置的指示器。
- 返回时恢复上一页滚动位置；不同页面不共享错误滚动位置。

### 10.3 预加载

- 对同源导航链接在 pointer enter 或键盘 focus 后延迟 80 ms 预取。
- `Save-Data`、减少数据模式或连接质量差时关闭预取。
- 一次只预取一个目标页面。
- 不预取编辑、删除、退出等有副作用或敏感内容的页面。

### 10.4 加载状态

- 预计超过 150 ms 的请求显示与真实布局一致的骨架。
- 已在 20 秒缓存中的数据先渲染，再后台刷新。
- 不使用全屏旋转器替代局部加载。
- 图片指定宽高或宽高比，避免布局位移。

## 11. 代码边界

### 11.1 样式

从单一大文件中拆出以下职责：

- `tokens.css`：色彩、排版、间距、圆角、动效变量。
- `base.css`：reset、字体、焦点、通用可访问性。
- `shell.css`：手机 Tab、平板图标栏、桌面侧栏、安全区。
- `components.css`：按钮、卡片、输入、状态、Toast、骨架。
- `pages.css`：各业务页面布局。
- `pet.css`：宠物安全区、状态和动画。

迁移期间保留旧类名兼容，最终不在同一元素上叠加两套互相覆盖的布局系统。

### 11.2 JavaScript

- `shell.js`：根据 `body[data-tab]` 生成导航与当前状态。
- `pet.js`：读取配置、管理状态机、播放动作、拖动定位和本地偏好。
- `transitions.js`：预取、跨文档过渡和滚动恢复。
- 现有 `api.js` 与 `ui.js` 继续负责数据和通用组件，不把业务请求塞进宠物模块。

所有前端模块使用现有无构建静态脚本兼容方式；若使用 ES Modules，必须在所有业务页面保持加载顺序一致。

### 11.3 事件接口

页面通过最小事件接口驱动宠物：

```text
knowtree:data-ready
knowtree:input-focus
knowtree:input-blur
knowtree:request-start
knowtree:request-success
knowtree:request-error
knowtree:inbox-changed
```

宠物模块只消费事件和页面可见数据，不直接修改业务状态。页面跳转使用普通链接或现有 `UI.go`，不新增宠物专用写入 API。

## 12. 错误与降级

- 宠物资源加载失败时隐藏动画，保留普通导航和文字提示。
- 本地存储不可用时使用内存状态，不阻断页面。
- View Transitions 失败时执行普通跳转。
- 浏览器不支持 WebP 时使用透明 PNG 回退。
- 网络错误、AI 错误和文件错误继续使用现有稳定错误码与中文提示。
- 宠物动画不得延迟采集提交、阅读渲染或保存结果。

## 13. 无障碍

- 主导航使用 `nav` 和明确 `aria-label`。
- 宠物入口使用可聚焦按钮语义，不以纯装饰图片接收键盘焦点。
- 气泡使用 `role="status"` 或 `aria-live="polite"`，不抢当前输入焦点。
- 装饰性动作不重复播报；只播报可执行信息。
- 所有触控目标至少 44 × 44 px。
- 焦点环保持可见，纸面和暗色面分别有足够对比。
- 颜色不是状态的唯一表达方式。
- 支持 `prefers-reduced-motion` 和站内“减少宠物动作”。
- 动画暂停时，所有入口、按钮和导航仍可完成全部流程。

## 14. 性能预算

- 手机 4G 下目标 LCP 小于 2.5 秒。
- CLS 小于 0.1。
- INP 目标小于 200 ms。
- 首屏不加载全部六张宠物动作帧；只加载当前帧，其余在 idle 后按需预取。
- 宠物 WebP 总资源不超过 250 KB；当前六帧约 182 KB。
- 单个额外字体不超过 120 KB，默认远端字体数量为零。
- 宠物动画连续运行时避免主线程 JavaScript 循环，优先 CSS transform。
- 页面不可见时暂停动画和定时器。

## 17. 验收标准

- 所有业务页面共享同一套颜色、字体、间距、卡片和按钮规则。
- 手机没有横向溢出，桌面内容有合理最大宽度。
- 首页第一屏可以直接开始采集，同时能看到最多一条宠物提示。
- 第九个及之后的分类可以在知识库访问，首页不再静默隐藏。
- 宠物仅在登录后的业务页面出现，永久常驻、可拖动，且不遮挡主要操作。
- 输入期间宠物保持静止且不弹新提示。
- 坐下与叼叶动作帧不包含相邻姿态、被裁切叶片或背景残片。
- 用户点击宠物只能进入流程，不能触发写操作。
- 减少动态效果后所有功能仍完整可用。
- 页面切换无整页白屏闪烁；不支持高级过渡时正常降级。
- 现有认证、采集、AI、阅读、编辑、审核和部署流程无功能回退。
- 全部现有测试、生产构建和部署预检通过。
