# 知树 KnowTree — 后端接口对接清单（M0）

> 2026-11-02 部署修订：前端与 API 现在同源部署在一个 Vercel / Express 应用中；浏览器不再手填 API Base、Supabase URL 或 access token。生产代码已移除扣子 CDN、Coze SDK、工作负载身份和直连 Postgres。

> 权威来源：`apps/api/src` 当前生产代码。
> 前端对应目录：`apps/web`。
> 更新时间：2026-11-03。

## 〇、接口总则

接口覆盖收录、去重、AI 归类、互链、检索、回溯、导出和注销。字段与行为以当前代码和本文档为准。

---

## 1. Base URL 与鉴权方式

| 项 | 值 |
|---|---|
| Base URL | 同源 `/api/v1`；本地默认为 `http://localhost:9091/api/v1` |
| 统一前缀 | **所有业务接口在 `/api/v1` 下** |
| 鉴权方式 | **自定义请求头 `x-session`**（不是 Bearer，也不是 Cookie） |
| 公共配置 | `GET /api/v1/config` 只返回 `supabaseUrl` 与 publishable key |
| 凭证来源 | 客户端通过 Supabase Auth 注册或登录，把 `session.access_token` 塞进 `x-session: <access_token>` |
| 失效语义 | 无 token → `401 {error:"请先登录"}`；token 校验失败 → `401 {error:"认证失败"}` |
| 数据隔离 | 服务端按 `user_id` 过滤；全表 RLS（`auth.uid()=user_id`） |

> ⚠️ 前端把 access_token 放请求头 **`x-session`**，不要用 `Authorization: Bearer`，也不依赖 Cookie。

## 2. CORS

- 默认前后端同源，不需要 CORS。
- 仅本地跨域开发时设置 `ALLOWED_ORIGIN`，只允许逗号分隔的明确来源。
- 不使用 Cookie；token 走 `x-session` 头。
- Body 上限 `50mb`（`express.json({limit:'50mb'})`）

## 3. 全局错误结构

```jsonc
{ "error": "错误消息" }
```
- 500 统一 `{error}`；404 业务类 `{error:"条目不存在"}` / `{error:"任务不存在"}`。
- 前端处理 401（跳登录）、409/429（若出现）、5xx（保留当前页 + toast 重试）。注意字段名是 `error`，不是 `code/message`。

## 4. 领域模型与枚举（写死字段）

**EntryStatus（`entries.status`，处理流水线）**
`pending → parsing → parsed → classified → linked`，失败 `failed`

**ClassificationStatus（`entries.classification_status`，归类结果）**
| 值 | 含义 | 触发条件 |
|---|---|---|
| `auto` | 已自动归类 | 置信度 `≥ auto_classify_threshold`(默认0.75)，或用户手动设了分类 |
| `pending_review` | 待确认 | 置信度 `0.50–0.75`，只写 `suggested_category_id`，不落正式分类 |
| `uncategorized` | 未分类 | 置信度 `<0.50`，不新建分类 |

**CaptureType**：`web | manual | clip | image`
**JobStatus**：`pending | running | succeeded | failed`
**JobType**：`parse | classify | link | dedupe | daily_recall | export | delete_account`
**RecallStatus**：`pending | done | skipped`

## 5. 「卡片状态 ok / pending / dup」映射

后端**没有** `ok/pending/dup` 状态字段，用两个字段 + 收录响应表达：

| 前端概念 | 落到哪 | 取值 |
|---|---|---|
| `ok`（已收录可用） | `entries.status` | `parsed/classified/linked` 任一 ✅ |
| `pending`（处理中） | `entries.status` | `pending`（待解析）、`parsing`（正在抓取） |
| `pending`（归类待确认） | `entries.classification_status` | `pending_review`（0.50–0.75） |
| `dup`（重复） | **不在 entry 上** | 见下 |

**"重复"不落地为 entry 状态字段：**
- 精确重复：收录接口顶层响应 `status:'hash_duplicate'` + `dup_of`（已存在条目 id）+ `weight`（+1 次数）
- 向量相近：收录响应 `dup_suggestions[]`（相似度 ≥0.90 候选），**仅提示、默认不自动合并**

> 前端展示"重复/去重"标记，应读**收录接口返回**的 `status` / `dup_suggestions`，而不是 `entry.status`。

## 6. 收录（capture）同步/异步 + P90

- **同步创建**：`POST /entries/ingest` 同步完成【哈希去重 + 写库 + 向量化（去重建议）+ 建任务】，返回**已创建完整 entry + `jobs[]` 任务 id 列表**。
- **异步重活**：解析（仅当 URL 无正文）、AI 归类（classify）、互链（link）写入 `jobs` 队列。收录响应后由 Vercel `waitUntil` 立即消费；每日 Cron 处理到期补偿任务。前端拿到 `jobs[]` 后**轮询 `GET /jobs/:id`** 看 `status`/`result`。
- **实测 P90**（dev 沙箱，含一次 embedding，10 次采样）：正常新建 ≈ **0.55–0.65 s**，中位约 0.39 s；哈希去重命中毫秒级。**为本地参考非生产 SLA**。

## 7. 全量接口明细

> `health`、`config` 免用户鉴权；`cron/jobs` 使用 `CRON_SECRET`；其余业务接口需 `x-session` 头。字段均为 **snake_case**。

### 7.1 系统
**`GET /api/v1/health`**（免鉴权）→ `{ "status":"ok" }`

**`GET /api/v1/config`**（免用户鉴权）→ `{ "supabaseUrl":"https://xxx.supabase.co", "supabaseKey":"sb_publishable_xxx" }`

> 只返回前端登录所需的公共配置，绝不返回 Supabase secret key。

### 7.2 账号 / 配置
**`GET /api/v1/bootstrap`** → 200
```jsonc
{ "categories":[], "entries":[], "me":null, "recalls":[] }
```
> 首屏聚合接口。服务端只执行一次鉴权，并行查询分类、前 100 条知识、用户配置和回溯；`me` 或 `recalls` 失败时返回 `null`/空数组，不阻断主数据。

**`GET /api/v1/me`** → 200
```jsonc
{ "user":{ "id":"uuid","email":"a@b.c","phone":null },
  "profile":{ "user_id":"uuid","display_name":null,"avatar_url":null,
    "daily_recall_enabled":true,"daily_recall_count":3,
    "auto_classify_threshold":0.75,"review_threshold":0.5,
    "auto_merge_enabled":false,"created_at":"ISO","updated_at":"ISO" } }
```
> 首次访问自动建 profile + 预置 4 分类（技术/阅读/工作/生活）。

**`PATCH /api/v1/me`** — Body（均可选）：`{ "display_name","avatar_url","daily_recall_enabled","daily_recall_count","auto_classify_threshold","review_threshold","auto_merge_enabled" }` → 200 `Profile`

**`DELETE /api/v1/me/account`** — 注销（彻底删数据+auth 账号）→ `{ "deleted":true }`

### 7.3 分类 categories（= 前端的"节点/树"）
**`GET /api/v1/categories`** → 200 `Category[]`
```jsonc
[{ "id":"uuid","user_id":"uuid","name":"技术","description":null,
   "parent_id":null,"icon":null,"deleted_at":null,
   "created_at":"ISO","updated_at":"ISO" }]
```
> 按 name 升序、排除软删除。**返回扁平列表（parent_id 反映层级），无 count、无子孙聚合字段。**

**`POST /api/v1/categories`** — `{ "name","description"?,"parent_id"?,"icon"? }` → 201 `Category`
**`PATCH /api/v1/categories/:id`** — 同上可改字段 → 200 `Category`
**`DELETE /api/v1/categories/:id`** — 软删除并解除其下条目 category_id → `{ "deleted":true }`

> ⚠️ **无 `/nodes` 或树聚合接口**。要"分类下含子级条目的聚合 count"，只能前端按 `categories.parent_id` 递归建树、再逐分类调 `GET /entries?category_id=` 统计；或后端后续补聚合接口（本期未实现）。

### 7.4 收录与条目 entries
**`POST /api/v1/entries/ingest`**（capture）— Body：
```jsonc
{ "url"?: "https://...",   // 可无 content，仅 url → 触发异步 parse
  "content"?: "正文文本",
  "title"?: "标题",
  "captureType"?: "web|manual|clip|image" }
```
→ 201 两种返回：
```jsonc
// A) 新建
{ "status":"created",
  "entry":{ /* Entry，见下 */ },
  "dup_suggestions":[ { "entry_id":"uuid","title":"x","similarity":0.92 } ],
  "jobs":["jobId1","jobId2"] }   // classify、link（可能含 parse）

// B) 精确重复（不新建，权重+1）
{ "status":"hash_duplicate","entry":{/*已有*/},"dup_of":"uuid","weight":2,
  "message":"已存在相同内容，未重复收录（权重+1）","jobs":[] }
```
`Entry` 字段：
```jsonc
{ "id","user_id","source_id"|null,"category_id"|null,"title","summary"|null,
  "content","content_hash","source_url"|null,"capture_type",
  "status":"parsed","classification_status":"uncategorized",
  "classification_confidence"|null,"suggested_category_id"|null,
  "weight":1,"recall_count":0,"last_recalled_at"|null,
  "deleted_at"|null,"created_at","updated_at" }
```

**`GET /api/v1/entries`** — Query：`status`?、`category_id`?、`classification`?、`q`?(标题/正文 ilike，非语义子串)、`page`?=1、`size`?=20 → 200 `Entry[]`（created_at 倒序）
**`GET /api/v1/entries/:id`** → 200 `Entry` / 404
**`PATCH /api/v1/entries/:id`** — `{ "title"?,"content"?,"summary"?,"category_id"? }`
> 改 content 重算 content_hash；显式设 category_id → classification_status 置 auto、confidence 置 1；设 null → uncategorized。
→ 200 `Entry`
**`DELETE /api/v1/entries/:id`** — 软删除 → `{ "deleted":true }`

### 7.5 子资源：版本 / 互链 / 归类 / 合并
**`GET /api/v1/entries/:id/versions`** → 200 `EntryVersion[]`（倒序 ≤50）
**`POST /api/v1/entries/:id/versions`** — `{ "note"? }` → 201 快照当前内容
**`GET /api/v1/entries/:id/links`** → 200 出链（score 降序，含目标摘要）
```jsonc
[{ "id","score","reason":null,"target_entry_id","created_at",
   "target":{ "id","title","summary","source_url" } } ]  // target 可能为 null
```
**`POST /api/v1/entries/:id/classify`** — 触发 AI 归类（同步）→ 200 `Entry`
**`POST /api/v1/entries/:id/link`** — 触发互链（向量≥0.70 取 1–3 条）→ `{ "count":2, "links":[{ "target_id","score" }] }`
**`POST /api/v1/entries/:id/merge`** — `{ "target_entry_id":"uuid" }`（本条目并入 target）→ 200 `Entry`（合并后 target；源条目硬删，权重累加、内容入目标版本）

### 7.6 检索 search（关键词+语义，相关度×新鲜度）
**`GET /api/v1/search`** — Query：`q`（必填）、`limit`?=20 → 200
```jsonc
{ "items":[
    { "id","title","summary","source_url","category_id",
      "classification_status","created_at",
      "score":0.813,          // relevance*freshness
      "semantic_similarity":0.87, "keyword_hit":true } ],
  "counts":{ "semantic":12, "keyword":3 } }
```
> 评分：`relevance = semantic*0.7 + keyword*0.3`（标题命中 keyword=1、正文=0.6），`score = relevance * e^(-0.015*ageDays)`。

### 7.7 每日回溯 recalls（1–3 张按权重）
**`GET /api/v1/recalls`** — Query：`date`?（YYYY-MM-DD 默认今天）→ 200 `DailyRecall[]`
**`POST /api/v1/recalls/generate`** — `{ "date"? }` → `{ "date","created":2,"items":[DailyRecall],"existing":[DailyRecall] }`（最多 profile.daily_recall_count，上限3）
**`PATCH /api/v1/recalls/:id`** — `{ "status":"done" }`（pending|done|skipped）→ 200 `DailyRecall`

### 7.8 导出 export
**`GET /api/v1/export?format=md|json`**（缺省 md）
- `md` → `text/markdown`（`# 知树…`，含分类名/来源/摘要/正文前5000字）
- `json` → `application/json`：
```jsonc
{ "app":"知树 KnowTree","exported_at":"ISO",
  "entries":[ { "id","user_id","source_id","category_id","title","summary","content",
     "content_hash","source_url","capture_type","status","classification_status",
     "classification_confidence","suggested_category_id","weight","recall_count",
     "last_recalled_at","deleted_at","created_at","updated_at" } ] }
```
> 注意 json 返回的是 **JSON 字符串**（需 `JSON.parse`），字段 snake_case，已剔除 embedding。

### 7.9 任务队列 jobs
**`GET /api/v1/jobs`** — Query `status`? → 200 `Job[]`（倒序）
**`GET /api/v1/jobs/:id`** → 200 `Job` / 404
```jsonc
{ "id","user_id","job_type":"classify","payload":{ "entry_id":"uuid" },"status":"succeeded",
  "attempt_count":1,"max_attempts":3,"next_run_at":"ISO","last_error":null,
  "result":{ "entry_id":"uuid","classification_status":"auto","confidence":0.95,
             "suggested_category_id":"uuid" } | null,
  "created_at","updated_at" }
```
- parse 失败退避 30/60/120s，超 3 次置 `failed` 写 `last_error`。
> 用户 API 不再暴露 `POST /jobs/run`。全队列消费只允许通过受 `CRON_SECRET` 保护的 `GET /api/v1/cron/jobs`。

## 8. 前端接入要点

1. **注册 / 登录**：`register.html` 调用 Supabase 邮箱注册。确认邮件回到 `login.html` 时解析 URL hash 中的 token；登录后把 `access_token` 放 **`x-session`** 头。
2. **收录**：`/entries/ingest` 同步拿回 entry + jobs；随后轮询 `GET /jobs/:id`（或复读 entry.status）展示"处理中→已归类/已互链"。
3. **去重**：以 ingest 响应的 `status:'hash_duplicate'`、`dup_suggestions` 为准；自动合并需用户确认，调 `POST /entries/:id/merge`（符合"保守提示为主"）。
4. **分类**：后端返回扁平 `categories` + `parent_id`。首页构建知识树，知识库通过 `library.html?category=<id>` 筛选。
5. **字段 snake_case**，搜索/导出等聚合结构见上，勿按 camelCase 假设。
6. 你原提案（cards/nodes/status ok-pending-dup）与本文档不一致处，**以本文档为准**；字段映射见第 5 节。
