## 二、工程环境

- **纯静态 HTML**，**不是 Expo / React Native / Vue**。无框架、无 npm、无构建步骤、无 CDN 依赖。
- 多页应用（MPA），页面间靠真实 `location.href` 跳转 + query 参数，无前端路由。
- 资源：`assets/app.css`（样式与设计 token）、`assets/store.js`（数据层，唯一需要替换的文件）、`assets/ui.js`（壳层/组件/工具函数）。
- 每页 `<body data-page-id="...">` + `data-tab`（tree/lib/me），`ui.js` 统一渲染三 Tab 底栏。
- 布局：移动优先，桌面端 `max-width:430px` 居中；触控目标 ≥44px；暗底 `#0A0A0B` + 唯一暖金 `#C9A96B`。
- 持久化：当前全部走 `localStorage`，键名 **`knowtree_v1`**，结构 `{ cards: [], lastSeen: {}, settings: {} }`。

## 四、跳转逻辑

```
index(树)
 ├─ 点节点           → node.html?node=<nodeId>
 ├─ 点最近收录卡片   → detail.html?id=<cardId>
 ├─ 待确认横幅       → inbox.html
 ├─ ＋/丢一条(FAB)   → capture.html
 ├─ 每日回溯入口     → review.html
 ├─ 搜索             → search.html?q=
 └─ 底栏 Tab         → index / library / me

library
 ├─ 分段：全部 | 收藏 | 待确认（本地筛选，不换页）
 ├─ 卡片             → detail.html?id=
 ├─ 待确认空态       → inbox.html
 └─ 搜索             → search.html

inbox
 ├─ 逐条：确认(suggestedNode) / 改节点 / 合并到 dupOf / 保持独立
 ├─ 处理后留在本页，全部清完显示空态 → index
 └─ 撤销             → 本地 undo 栈（最近 10 步）

detail
 ├─ 点节点标签       → node.html?node=
 ├─ 待确认卡         → inbox.html
 ├─ 删除             → 软删除 + toast「撤销」（30 天可恢复）
 └─ 返回             → history.back()

node  → detail.html?id= ；空态 → index
review → 逐张：记住了(markSeen) / 看详情(detail?id=) ；结束后 → index
capture → 提交后展示「处理中」，约 1.2s 后跳 inbox.html 并 flash 提示
me     → 导出(JSON 下载) / 回收站(恢复) / 重置 / 清空 → 均留在本页
```

## 五、数据模型（前端已用字段，建议后端 1:1 对应）

```json
{
  "id": "c1",
  "title": "PPO 的优势函数估计",
  "summary": "一句话摘要，列表页展示",
  "body": ["正文段落 1", "正文段落 2"],
  "nodeId": "rl",
  "status": "ok",
  "suggestedNode": "rl",
  "confidence": 0.62,
  "dupOf": "c1",
  "sim": 0.91,
  "tags": ["强化学习", "PPO", "GAE"],
  "source": "arXiv · 1707.06347",
  "createdAt": "2026-10-16T02:11:00.000Z",
  "starred": false,
  "deleted": false,
  "mergedInto": null,
  "links": [{ "to": "c2", "sim": 0.88 }]
}
```

字段约定：

- `id`：字符串即可（`c1`/uuid/雪花都行，前端只做字符串拼接）。
- `status`：`ok`（已入树）｜`pending`（待确认）｜`dup`（疑似重复待处理）。
- `suggestedNode` / `confidence`：仅 `pending` 有；`dup` 用 `dupOf` + `sim`。
- 规则（后端判定，前端只渲染）：
  - `confidence` 0.50–0.75 → `pending` + `suggestedNode`（进收件箱，给建议）
  - `confidence` < 0.50 → `pending`，**不带 suggestedNode**（进未分类，不给建议）
  - `sim` ≥ 0.90 → `dup` + `dupOf`
- `deleted`：软删除，30 天内可 `restore`。
- `body`：字符串数组（段落），不要返回 HTML。
- 时间：ISO 8601 字符串。
- 节点：`{ id, name }`，前端需要 `count`（该节点下卡片数，含子孙节点聚合）。

预置数据（可作联调样例）：7 节点 `robotics / rl / papers / algo / math / control / cog`，11 卡 `c1–c11`，其中 `c10`(0.62)、`c11`(0.71) 为 pending，`c9` 与 `c1` sim 0.91 为 dup。

## 六、前端需要的接口约定（建议 REST，可协商）

Base：`/api`，全部 JSON（导出除外）。鉴权：`Authorization: Bearer <token>`；若你们用 Cookie Session 也可以，只需告诉我，我改成 `credentials:'include'`。

| # | 方法 & 路径 | 请求 | 响应 | 对应页面动作 |
| --- | --- | --- | --- | --- |
| 1 | `POST /api/cards/capture` | `{text, source?}` | `202 {cardId, status:"processing"}` | capture 提交 |
| 2 | `GET /api/cards/{id}` | — | `Card`（`status:"processing"` 时前端继续轮询，P90 ≤8s） | capture 轮询 |
| 3 | `GET /api/cards` | `?status=&nodeId=&starred=&deleted=&q=&limit=&cursor=` | `{items:[Card], nextCursor}` | library / node / inbox / search |
| 4 | `PATCH /api/cards/{id}` | `{nodeId?, starred?, status?}` | `Card` | 改节点 / 收藏 / 保持独立 |
| 5 | `DELETE /api/cards/{id}` | — | `204` | 删除（软删） |
| 6 | `POST /api/cards/{id}/restore` | — | `Card` | 回收站恢复 / toast 撤销 |
| 7 | `POST /api/cards/{id}/merge` | `{intoId}` | `Card` | 合并重复 |
| 8 | `POST /api/inbox/process-all` | — | `{processed:n}` | 收件箱「全部处理」 |
| 9 | `GET /api/nodes` | — | `{items:[{id,name,parentId,count}]}` | 首页树 / 节点页 |
| 10 | `GET /api/nodes/{id}/cards` | `?limit=&cursor=` | `{items:[Card]}` | node.html |
| 11 | `GET /api/search` | `?q=` | `{nodes:[Node], cards:[Card]}` | search.html |
| 12 | `GET /api/review/queue` | `?limit=3` | `{items:[Card]}` | review.html |
| 13 | `POST /api/review/{cardId}/grade` | `{grade:"again"\|"hard"\|"good"\|"easy"}` | `{nextDueAt}` | review「记住了」 |
| 14 | `GET /api/stats` | — | `{total, nodes, week}` | me.html 三个数字 |
| 15 | `GET /api/export` | `?format=json\|md` | 文件流（`Content-Disposition`） | me「导出」 |
| 16 | `GET/PATCH /api/settings` | `{reviewReminder?}` | `{reviewReminder}` | me「每日提醒」 |
| 17 | `POST /api/auth/logout` | — | `204` | me「退出登录」 |

统一错误体：`{ code, message }`，HTTP 状态码语义化；前端需要处理 `401`（跳登录）、`409`（重复冲突）、`429`（限流）、`5xx`（保留当前页 + toast 重试）。

## 七、集成方式（我这边要做的改动，范围很小）

1. 新增 `assets/api.js`，把 `assets/store.js` 里 `window.KT` 的同名方法改成 `async` 网络请求（方法名、返回结构保持不变）。
2. 页面里的 `KT.xxx(...)` 调用改成 `await KT.xxx(...)`，`ui.js` 与 HTML 结构、CSS 不动。
3. 列表/详情加 `loading`（骨架）与 `error`（重试）状态；capture 增加轮询 `GET /api/cards/{id}`。
4. `localStorage` 只保留 `knowtree_token` 与「提醒开关」缓存，业务数据全部交给后端。
