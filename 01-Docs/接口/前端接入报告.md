## 二、页面动作 → 接口（实际调用）

| 页面动作 | 接口 |
| --- | --- |
| 任意页面启动 | `GET /categories` + `GET /entries?page=1&size=100` + `GET /me` + `GET /recalls`（并发，401 自动跳 `login.html`） |
| 首页知识树 | 上面 4 个；节点计数用 `categories.parent_id` 前端递归聚合 |
| 知识库 全部 / 待确认 / 未分类 | 本地从 `/entries` 结果分片（`classification_status` 判定） |
| 详情页 | `GET /entries/:id` + `GET /entries/:id/links` |
| 详情页 改分类 | `PATCH /entries/:id {category_id}` |
| 详情页 删除 | `DELETE /entries/:id`（软删） |
| 待确认 就这样 / 选分类 | `PATCH /entries/:id {category_id}`（置信度由后端置 1、状态置 auto） |
| 待确认 全部处理 | 逐条 `PATCH /entries/:id`（串行，单条失败不阻断） |
| 疑似重复 合并 | `POST /entries/:id/merge {target_entry_id}` |
| 疑似重复 保留两条 | 纯前端清除提示（不调用接口） |
| 收录 | `POST /entries/ingest {content, captureType:'manual'}` → 拿 `jobs[]` → 轮询 `GET /jobs/:id`（1.2s，20s 上限）→ `GET /entries/:id` 刷新终态 |
| 搜索 | `GET /search?q=&limit=20`（260ms 防抖，带 seq 丢弃过期响应） |
| 每日回溯 | `GET /recalls`，为空时 `POST /recalls/generate`；「记住了」`PATCH /recalls/:id {status:'done'}`，「没印象」`{status:'skipped'}` |
| 我的 统计 | 由 `/entries` 结果本地算 total / 有内容的分类数 / 近 7 天 |
| 我的 导出 | `GET /export?format=json` → Blob 下载 |
| 我的 每日回溯开关 | `GET /me` 读 `daily_recall_enabled`，`PATCH /me {daily_recall_enabled}` 写 |
| 我的 注销 | `DELETE /me/account` → 清 token → 回登录页 |

## 三、字段映射（后端 → 页面视图模型）

`toCard(entry)` 在 `api.js` 内完成转换，页面沿用原有字段名，渲染代码基本未改：

| 视图字段 | 来源 |
| --- | --- |
| `id / title / summary / createdAt` | `entry.id / title / summary / created_at` |
| `body[]` | `entry.content` 按空行拆段 |
| `nodeId` | `entry.category_id` |
| `suggestedNode` | `entry.suggested_category_id` |
| `confidence` | `entry.classification_confidence` |
| `source` | `entry.source_url`，否则 `capture_type` 映射（web/manual/clip/image） |
| `tags[]` | 后端无 tags 字段，用所属分类名占位 |
| `status` | 见下 |
| `dupOf / sim` | 来自 ingest 响应的 `hash_duplicate.dup_of` 或 `dup_suggestions[].similarity`（存 localStorage `knowtree_dups`，刷新仍在） |
| `links[]` | `GET /entries/:id/links` → `{target_entry_id, score}` |

状态映射：

| 视图 status | 判定 |
| --- | --- |
| `processing` | `entry.status ∈ {pending, parsing}` |
| `failed` | `entry.status = failed` |
| `pending`（待确认） | `classification_status ∈ {pending_review, uncategorized}` |
| `dup` | 有 ingest 去重提示且已过解析阶段 |
| `ok` | 其余（parsed / classified / linked） |

## 五、需要后端补的（阻塞程度从高到低）

1. **可访问的 Base URL**：现在是 `http://<host>:9091`，前端跑在 https 预览域上会被浏览器拦（混合内容），且 `localhost` 指的是用户本机。要真正联调，需要一个 https 公网地址，或明确「前端在本机打开、后端本机跑」的用法。
2. **Supabase URL + anon key**：契约只说用 Supabase Auth 登录，没给前端可用的项目地址与 anon key，所以邮箱密码登录目前是「已实现但未配置」，只能用粘贴 access_token 的方式进。
3. **列表分页没有 total**：`GET /entries` 只返回数组，前端只能 `size=100` 拉一页，超过 100 条统计与「全部」列表会不准。建议返回 `{items,total}` 或 `X-Total-Count` 头。
4. **收藏**：Entry 无 `starred` 字段，也没有收藏接口。前端详情页收藏按钮目前点了只提示「暂未提供」。要么加字段 + 接口，要么这版砍掉收藏入口（知识库分段已改为「未分类」）。
5. **回收站 / 恢复**：`DELETE` 是软删但没有任何查询已删或恢复的接口，前端「回收站」入口点了只提示不支持，删除也不可撤销。需要 `GET /entries?deleted=1` + `PATCH /entries/:id {deleted_at:null}` 或 `POST /entries/:id/restore`。
6. **分类 count**：`GET /categories` 无 count、无子孙聚合，现在是前端递归聚合（数据量小没问题），条目多了建议后端补 `count`。
7. **回溯评分粒度**：现在只有 `pending/done/skipped`，前端按钮是「记住了 / 没印象」。如果要做 again/hard/good/easy 四档，需要后端扩展 `PATCH /recalls/:id` 的取值并回写下次到期时间。

## 六、怎么跑起来

1. 后端起在 `http://<host>:9091`，确认 `GET /api/v1/health` 返回 `{"status":"ok"}`。
2. 打开 `login.html`：填 API Base（含 `/api/v1`）→ 粘贴 Supabase `access_token` → 点「测试连接」→「进入」。
3. 想换回邮箱密码登录：在登录页填 Supabase URL 与 anon key，保存后即可用邮箱密码取 token。
4. 凭证与配置都存在浏览器 localStorage（`knowtree_token` / `knowtree_cfg`），换设备需重新填。
